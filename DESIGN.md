Program overview:

1) Two images are passed into the program, each containing the Object Of Reference (OOR) or t-shirt cropped. Both should be from the same image and are manually cropped by the user.

2) Background of each image is turned transparent and replaced with a blank white background, making it easier for contours and corners to be found. Functions called: removeBG().

3) Clean background images are passed to a respective OOR and t-shirt measure() function returning pixel measurements. The measurements are chest length, shirt length for t-shirt and length, width for OOR. Functions called: preprocess(), measure_tshirt(), measure_rect_object().

4) Using the real life OOR dimensions (hard coded number) and OOR pixel measurements, the shirt measurements can be calculated



My final project takes in an image of a t-shirt with a reference object (OOR) and undergoes four discrete steps: image preprocessing, object detection and division, finding t-shirt pixel measurements, and finding OOR pixel measurements returning the measurements of the t-shirt in inches. These measurements are provided by finding the key points - top and bottom, left armpit and right armpit. I make use of functions from OpenCV, sci-kit, PIL, rembg, and imutils libraries to detect contours and corners as well as the remby library to remove image backgrounds.


Image preprocessing is the first and most important step - it is not possible to find the correct contours or corners if the image is not prepared correctly. Through much trial and error, I have found this statement to be frustratingly true. For example, 'samples/purple1.jpg' is shot on a wood background. Passing it to my preprocessing() function will result in a noisy image; the wood grains in the background will show up as edges, confusing the findContours() algorithm and making it impossible to properly isolate and find the key points. To avoid this, the object or t-shirt must be isolated. Professionally shot and edited images from clothing websites are the ideal, my code finds all the correct key points. To remove the background, I make use of a library called rembg, which is specialized in finding a foreground object and turning the background transparent. Ideally, I would have done this myself but all my attempts at object detection failed. That being said, rembg is not perfect. If you output images before/after and look very closely at the edges, you'll notice that some slight blurring occurs. This blurring is actually significant in finding corners/contours and results in a less accurate end product. 

My function removebg() makes use of rembg.remove() to turn the image background transparent and then creates a new white blank canvas to overlay the object onto. The white background is required because transparent images just do not work with findContours(); I'm not sure why it doesn't, I just know from trying it out and seeing the results.
My preprocessing() function, which uses almost exclusively OpenCV functions and is called before finding contours, applies grayscale, gaussian blur is applied to remove noise, and a bilateral filter. The bilateral filter, which blurs an image without smoothing the edges is a crucial step. I have had many issues in image backgrounds where findContours() will pick up on wood grains or specks or just random things, but bilateral filtering will smooth these out and ensure little to none of this is picked up by findContours(). This is all setup for the canny algorithm, which renders the image in black (background) and white (edges). Dilation and erosion are the last step. Dilation augments to join any close disjointed points then erosion shrinks everything back down to their normal size. The end result is ensuring (mostly) contiguous edges. It is at this point where the image is passed off to another function to find its contours.


I could not get object detection working, instead my program relies on the user to manually crop the OOR and t-shirt out of the same image and pass them into the program separately. My initial attempts at primitive object detection involved preprocessing, like above, and then using the contours from edges to draw bounding rectangles (cv2.boundRect) around each set of contours found. In theory, there would be only two objects in frame so this would always detect the t-shirt and object. In practice it does not work like this. Textures in backgrounds gave me issues, graphics on t-shirts gave me issues, and sometimes it would not pick up on t-shirts, thinking the entire image was a single image. Even with the bilateral filter applying my object detection was not consistent, so I decided with the low-tech, tedious approach of having to manually crop each image for t-shirt and object. I tried some machine learning approaches but I really did not know what I was doing and could not get any real results.

What are the measurements of a t-shirt? Generally one could quantify it with three measurements - the shoulders, the chest and the length. From there one could roughly approximate how it would fit. Those are the measurements I look to quantify in measure_shirt().
The measure_shirt() function makes use of the Harris Corner Detection algorithm, cv2.cornerHarris() (around 1000 points) but this function is just a more efficient findContours() (about 10k points). Imagine an outline of a t-shirt, flat on the ground - this is what findContours() returns. We only need a few key points that will allow us to calculate the measurements of the t-shirt. These key points are the top, bottom, left, right, left bottom corner (lbc), right bottom corner (rbc), left armpit, right armpit, left shoulder and right shoulder. Some of these points require other key points to calculate, some can be found right away.
The top, bottom, left and right points are consistent and easily found. Going back to the outline of the t-shirt: the top point is around the collar while the bottom is at the bottom of the t-shirt. The left and right are the tops of the sleeves. Coordinates are different in openCV, with Y getting smaller as you go higher. To calculate top/bot points, you find the minimum/maximum of the Y coordinate of the array of points found by cornerHarris(). Left and right are found via the minimum/maximum of the X coordinate on the same array. The left/right bottom corners share a Y coordinate with bot, but they are consistently and correctly found.

Armpits and shoulders are more difficult to reliably find. On a t-shirt the left pit shares a similar X value to the left bottom corner and is located between the leftmost point and lbc. Therefore we loop[ over a slice of array, bound between left and lbc (using array indexing) looking for a value where the X coordinate is similar to that of lbc but also is the greatest. The X value will be similar because the armpit is a straight shot up from the bottom corner of the shirt, greatest value because we want a value as close to the shirt as possible and X increases from left to right. The right armpit found in a similar way: loop over a slice of the array [right:rbc], looking for a similar X value to rbc. However, now we want the X values to be as small as possible since we are looking from the right. This methodology is not foolproof, sometimes it finds the pits far lower than they should be. The fix would be to find the proper Y coordinate but I have not found a consistent way to do that. I experimented with using lower bottom corner of the sleeves as a metric, but it was not reliable because where they drape depends on how the person poses the shirt in the photo, how the sleeves drop, etc.

Shoulders are approximately where the seams meet the sleeves. This poses a problem as contour/edge detection doesn't reliably count these as edges. You can leave noise in to return more than just the outline contours with findContours(), but then you run into the problem of having false positives like creases showing up as a contour. My method approximates shoulder points via the bottom corners. The shoulders, in general, tend to be smaller than the width of a t-shirt as t-shirts get smaller as you move upwards, but they are fairly close on the X coordinate. Using the same method to the armpits, we draw a line from the bottom corner straight up, but this time the points are bounded from the leftmost point to the first element in the array, or the rightmost point to the first element in the array. Going back to the outline of the t-shirt, we are only looking at the very top most points in the contour in order to find the shoulder. The downside that this method is very rough, I never found a completely correct shoulder measurement.

That is all the logic behind the method, this is what my code does. A backgroundless image is preprocessed (as described above) and casted into a numpy float32 before being fed into cv2.cornerHarris(). Values of confidence for corners are returned by the function, which is promptly converted in an np.array of pixel coordinates. With this array, corners[], key points of the t-shirt can be found. X/Y coordinates of corners[] with argmin() and argmax() yields the left, right, top and bottom points of the t-shirt respectively. The bottom point’s Y coordinate is similar to that of left/right bottom corner’s (lbc/rbc) Y coordinate while the lbc/rbc’s X coordinates are similar to left/right armpit. The isclose() function is used to find similarities - the aforementioned values must be within 5% of each other. From there measurements of the chest length and shirt length can be calculated by plugging in values to the distance formula (left pit, right pit and top, bottom).

Initially I tried to find OOR measurements by finding the contours of the object - similar to that of the t-shirt - and using those points to approximate some coordinates, but it wasn't very reliable. Unlike a t-shirt, we don't need about the exact coordinates of an object. All we need is the length and width. It is much more reliable to find the vertices of a bounding rectangle around the object. This approach is better in a couple of ways, irregular shapes throw the measurement off less, the vertex points are consistently found, and it's logically simpler.

A backgroundless image is passed to the measure_rect_object() function. The image undergoes preprocessing, as described above before being passed to cv2.findContours. Parameters “cv2.RETR_EXTERNAL” and “cv2.CHAIN_APPROX_SIMPLE” will ensure only exterior contour points and a reduced amount of contour points are returned. Again, we do not care about whatever points are inside the object, we only care for the outline of the object. Using some looping and cv2.contourArea, we find the largest contour which is the object. A rectangle is drawn by calling cv2.minAreaRect() on the contour points, the vertices are found by cv2.boxPoints() and then converted into an array, box[], by np.int0().

Here the logic is much simpler than that of measure_tshirt()'s. Box[], the bounding rectangle array is copied into Box2[]. Box2[]’s X coordinate is sorted by argsort() in ascending order to determine which vertex corresponds to which corner. Smaller X values determine left orientation while smaller Y values determine top orientation. Therefore the first two elements in the array are left-oriented with the larger Y being the top left corner. Similar logic can be applied for the last two elements. Very simple, very fast and no room for ambiguity. Plugging corresponding values into the distance formula yields OOR pixel width and length allowing for pixel per inch to be found and thereby shirt measurements. And that is how my program works.
